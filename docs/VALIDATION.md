## Автоматические проверки

- `npm test`: 25 из25 тестов — 13 серверных и12 проверок DOM/поведения. Фиксированный получатель, экранирование, валидация/размер/origin, honeypot, явное согласие с версией, повторные запросы, отказы сервиса и подписанные входящие callbacks. Реальные письма не отправляются.
- `npm run lint`: ESLint и Stylelint проходят.
- `npm run format:check`: форматирование проходит.
- `npm run build`: production-сборка проходит без Python.
- `npm run check`: 21 страница,1062 внутренних ссылки и адаптивных изображения; ошибок и предупреждений нет. Проверяются canonical/языки/структура/form contracts/языковая навигация и файлы srcset.
- Происхождение поддерживаемых растров: финальный скан production показал71 файл,0 без origin. WebP используют `.webp.json` sidecar, который сохраняется при хешировании сборки. AVIF из пользовательского handoff указан в `docs/ASSETS.md`; CLI не включает этот формат в свой scan.

Подробные результаты находятся в локальной игнорируемой папке `Reports/`. Это доказательства текущей сборки; после изменения исходников проверки запускают повторно.

## Браузер

Проверка через native Chrome159 на этом Mac:1440px desktop,390px phone и320px для длинных RU/UK текстов. Семь полноразмерных снимков: Apps desktop/mobile, UX desktop/mobile, RU Apps390, RU UX320, UK Privacy320. Для статической проверки движение остановлено; изображения загружены при посещении разделов до захвата. Движущиеся элементы также наблюдались в обычном режиме, без исчерпывающего прогона каждой игровой партии.

Проверены отображение четырёх продуктов, длинные заголовки/кнопки, переносы ссылок внизу, сравнение before/after и независимые полные пояснения, статичная связанная схема в режиме уменьшения движения, правовые документы и языковые адреса. Шесть замечаний независимого рецензента исправлены; повторный вердикт **ship** относится именно к этим шести исправлениям. Замечание об отсутствующем на полном снимке desktop-логотипе оказалось отложенной загрузкой при захвате: native снимок `Reports/desktop-footer.png` подтверждает его реальное отображение; код для этого не менялся.

В dev-сервере, где реальные письма выключены, форма с тестовым `example.invalid` адресом получила503: интерфейс показал честную ошибку и сохранил адрес. Тестовые значения затем очищены. Проверены открытие поддержки, первоначальный фокус, Escape и возврат фокуса к ссылке. Наблюдалось открытие/закрытие мини-игры. Успешный путь отправки проверен серверными тестами с подставным Resend-клиентом; доставка через настоящую production-конфигурацию требует отдельно согласованного письма.

Без JavaScript документы и локализованный контент находятся в HTML; формы скрыты с mailto-фолбэком. Это проверено по готовому HTML/CSS; отдельный полный браузерный прогон с отключённым JS не заявляется.

## Дополнительная проверка поведения

После повторного сравнения с предоставленным HTML восстановлено исходное перемешивание первого экрана: все четыре продукта присутствуют, нет повторов в тройке соседних карточек, копия набора продолжает карусель без шва. Это дополнительно проверено на100 перестановках. Полное покадровое равенство каждой анимации и каждого игрового исхода не заявляется.

Исправлены гонки при быстрых открытиях/закрытиях меню, поддержки и мини-игры; отложенная очистка больше не стирает заново открытое игровое поле. Форма блокирует редактирование и повторную отправку на время запроса, сохраняет данные и ключ повтора при сетевой ошибке. Дополнены управление клавиатурой, выбранные состояния сравнения и режим уменьшения движения при недоступном local storage. Модальное окно блокирует фон и на документных страницах, сохраняя прежнее состояние inert. Успешный статус подписки вынесен в отдельную строку и не оформляется как ошибка.

В native Chrome проверен полный путь браузер → HTTP `/api/forms` → настоящий `createFormsHandler` → локальный почтовый имитатор → ответ браузеру. Подтверждены: успешная подписка; отказ сервиса с сохранением адреса; успешный повтор с тем же idempotency key; успешная поддержка с выбранной через клавиатуру темой; успешная UX-заявка с выбранной категорией. Проверены открытие трёх мини-игр по очереди, ход и ответ компьютера в крестиках-ноликах, фокус в memory и Escape, клавиши canvas, клавиатурное переключение UX-примеров. На privacy-странице при поддержке фон исчезает из дерева доступности, Escape возвращает фокус к Support.

Native Safari дополнительно прошёл успешную подписку, открытие memory и Escape. После финального исправления размещения статуса повторно проверены Safari desktop и Chrome с RU-интерфейсом при320 CSS px: длинное подтверждение и согласие не перекрываются, кнопка и текст помещаются. В просмотренной Console Chrome новых ошибок не показано. Это контрольные сценарии, а не исчерпывающая матрица всех браузеров/устройств.

Локальные квитанции находятся в `Reports/quality-mail-receipts.json`. Использованы только адреса example.invalid и имитатор; настоящие письма не отправлялись. Dev-обработчик отдельно проверен на порту4190: корректный Origin принят, затем получен ожидаемый503 при выключенной почте вместо прежнего403 из-за жёстко заданного порта.
